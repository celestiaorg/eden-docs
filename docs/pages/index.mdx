# Eden docs: build on the Eden EVM network

Eden is an EVM network built using the [Evolve stack](https://github.com/evstack) and powered by Celestia for data availability.

## Overview

- EVM chain optimized for high throughput
- Built with Evolve Stack
- Built for EVM applications on Celestia
- Uses Celestia for data availability

## Features

- **EVM-compatible** - existing Solidity contracts, Hardhat/Foundry projects, and Ethers/Viem scripts work without changes
- **Single sequencer** - fast, predictable block production
- **Native TIA** - deposits through the Eden bridge

Eden also extends the EVM with powerful capabilities standard chains don't offer. [See what Eden gives developers](/why-eden).

Start with the [Eden developer portal](/developers) for quickstarts, CLI tools, testnet access, and agent resources.

## How to start

### Build an application

1. **Choose a network.** Start with [Eden testnet](/networks/testnet) for experiments,
   or use [Eden mainnet](/networks/mainnet). Copy the RPC URL and chain ID from that
   network's reference into your [wallet](/tooling/wallets) or development tools.
2. **Fund your address.** Get testnet TIA from the [testnet faucet](/networks/testnet#faucet).
   For mainnet, deposit TIA through the [Eden bridge](https://eden.zone/) before sending transactions.
3. **Deploy or connect.** Follow the [Foundry quickstart](/development-environments/foundry-quickstart)
   to deploy a contract, or connect an application with [viem](/frontend-libraries/viem-quickstart)
   or [wagmi](/frontend-libraries/wagmi-quickstart). These examples use mainnet settings;
   replace them with your chosen network's settings when testing.
4. **Check the result.** Look up your contract or transaction in the explorer linked
   from your network reference. Use the [developer portal](/developers) for next steps
   and [contact options](/contact) for help.

### Integrate the documentation

You only need an HTTP client such as `curl`, or an MCP-capable coding agent.
The documentation REST API and MCP server are public and read-only: no account,
API key, OAuth, agent registration, wallet, or TIA is required. Blockchain RPC
providers have separate credentials and rate limits; see your network reference.

1. **Choose an interface.** Use the [REST API](/api-reference) from scripts, or
   follow the [MCP quickstart](/use-the-docs-with-ai#quickstart) for a coding agent.
2. **Read a page.** List the available pages, then read `/networks/testnet` using
   the REST examples or MCP's `list_pages` and `read_page` tools.
3. **Verify access.** Confirm the response contains the page's Markdown, including
   its chain info and faucet section. Use the network's RPC endpoint for blockchain
   state and transactions; the documentation API only returns documentation.

## The stack behind Eden

Eden is powered by the **Evolve stack**:

| Component    | Description                                             |
| ------------ | ------------------------------------------------------- |
| `ev-node`    | Modular node engine connecting execution to Celestia DA |
| `ev-reth`    | High-performance EVM implementation                     |
| `ev-toolbox` | Tools for testing and deployment                        |

## FAQs

:::details[Is Eden its own network?]
Yes. Eden is a standalone EVM chain that uses Celestia for DA.
:::

:::details[Is this part of Celestia mainnet?]
Eden posts data to Celestia mainnet, but runs its own execution environment. Celestia only handles
consensus and data availability.
:::

:::details[Do I need TIA?]
Yes. Eden uses TIA as its native gas token. Use the Eden bridge to deposit TIA before sending
transactions.
:::

:::details[Can I launch my own network using Eden?]
No — Eden is for apps, not networks. But if you want to launch your own chain, check out the
Evolve stack.
:::

:::details[How is this different from other EVM chains?]
Eden adds protocol-level features that standard EVM chains don't offer: native batch transactions,
sponsored gas, and a 128 KB contract size limit. See [Why Eden](/why-eden) for the full breakdown.
:::
